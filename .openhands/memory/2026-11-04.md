## FK question: SET NULL vs no FK (owner follow-up)
- Owner asked to make `player_answers.question_id` nullable + `ON DELETE SET NULL` instead of
  dropping the FK. Tested A/B/C on real Postgres (scratch DBs `zp_fk_probe`, `zp_fk2`):
  A (no FK) id survives + report/CSV correct; B (nullable+SET NULL) id→NULL and `gameReport()`
  throws; C (NOT NULL + SET NULL) the quiz DELETE itself fails. Also B2: `updateQuiz` recreates
  every question row, so an ordinary editor save nulls attribution too. Conclusion: keep no FK.
- Added DB-level guard in `snapshot.integration.test.ts`; documented in migration comment, schema
  comment, and report §7 (incl. the legacy-game 409 edge case and the `game_snapshot_questions`
  alternative).
- Scratch DBs used and dropped: zp_fk_probe, zp_fk2, zeropeek_migtest, zeropeek_legacy,
  zeropeek_drift. Test DB recreated from migrations; `prisma migrate diff` = no drift.
