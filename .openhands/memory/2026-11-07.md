## Phase 6.5.3 – extended host control (implemented, branch `feat/phase-6-5-3-extended-host-controls`)

Branched from `origin/main` `2fa0c6b` (PR #30 merged). Order from the owner: pause/resume +
skip for the host. Also folded in the two open questions from the 6.5.2 report (lobby kick
control, host presence for players).

**Pause/resume design (the part worth remembering):**
- `limitMs(question) = timeLimit*1000 + ANSWER_GRACE_MS` is now the ONE place the "visible
  limit + grace" arithmetic lives — the timer, the late-answer guard and the pause maths all
  call it. Before this, the same expression was written out three times and a resume would
  have drifted from the clock.
- Pause freezes `remainingMs` server-side, clears the timer, and **shifts `openedAt` forward
  by the pause duration on resume** — so elapsed-time scoring continues as if the pause never
  happened. Re-arms the timer exactly once.
- Paused state is persisted as rows in the **existing `GameEvent` log** (`paused`/`resumed`/
  `skipped`) → **no migration, no new column**. `recoverCurrentQuestion` reads the last of
  `paused`/`resumed` to restore a paused game **paused** (no timer armed), and the last of
  `question`/`reveal`/`skipped` to restore the skipped flag.
- `revealInternal` returns unchanged while paused **unless** it is a skip — so a stray timer or
  a racing host click cannot un-pause the game. `submitAnswer` refuses while paused.
- Slide questions have no clock → pause is refused by the engine, and the frontend offers no
  Pause button for them (dead-button guard).
- **Skip = end early, do NOT void.** Already-awarded points stand. That is the conservative
  choice and is flagged as an open product decision for chrisB in roadmap §6.2 + the report.
  **RESOLVED (chrisB, 2026-11-07):** a skip now **neutralises** the question — points refunded.

**Two dead-button bugs found and fixed by cross-checking the frontend against the engine:**
1. While paused the engine refuses a plain reveal, so offering **Reveal** was dead — a paused
   question now offers only Resume + Skip.
2. `engine.pause` refuses a `slide`, so the **Pause** button was dead for slides.

**Bug I found in my own work while reviewing the diff:** `playerSync` returned
`result: null` during a skipped reveal, but the *live* `game:reveal` sends
`outcome: 'skipped'`. So a player who reconnected mid-skip was shown the live question again
instead of the skipped result. Fixed in the engine (report `skipped` from `playerSync`), not
by patching the frontend — the sync must equal the live event. Regression test added:
"reports a skipped question to a reconnecting player, not a verdict".

**Also:** `answers` handler now keeps `currentAnswers` in step with the DOM, otherwise a
pause/resume re-render (which redraws from `currentAnswers`) showed a stale answer count.
Removed an unused `hasAnsweredCurrentQuestion` method I had added.

**Host presence:** `/host` room size decides `connected`/`reconnecting`, debounced
(`PRESENCE_DEBOUNCE_MS`) so a reload does not flash at players; first value for a game is sent
without waiting. Only reachability leaves the server — never a phase, session or host data.
Player chip renders **only** while the host is away.

**Kick:** now lobby-only (removing a player mid-game would silently rewrite a live ranking)
and it tells the player *first*, then removes the rooms, then re-broadcasts the lobby — so the
roster never lists someone already told to leave.

**Gate:** typecheck 0 errors; `prettier --check .` clean; tests **201 + 318 + 89 = 608** green;
`prisma migrate status` = up to date; `npm run build` OK. Integration cases run against real
Socket.IO + real Postgres (J/K/K2/K3/L in `host-sync.integration.test.ts`, a "pause / resume /
skip" + slides block in `engine.integration.test.ts`, skip-report case in
`snapshot.integration.test.ts`).

**Owner decisions (chrisB, 2026-11-07) — the three open questions are now CLOSED:**
- **A. Skip neutralises the question.** Already-awarded points are refunded, the correct answer
  is neutralised, earlier questions untouched. New engine method `refundQuestion` does it in one
  transaction (idempotent → a re-entrant skip or a skip racing an end cannot double-refund).
  Every report marks the question as skipped: `gameReport.skipped`, a CSV `skipped` column,
  `quizStatistics.skippedGames`.
- **B. No solution on a skipped reveal.** `HostReveal` is a discriminated union whose skipped
  variant carries only `{ id, type, text }` — a leak is impossible **by construction**. The
  frontend `revealBody(reveal)` is the one pure builder for the reveal screen.
- **C. A slide cannot be paused.** Engine refuses pause/resume for a `slide`; the host console
  offers no Pause button. Tests added on both sides.

**CI caught a real bug (worth remembering):** `GameEvent.createdAt` is
**millisecond precision only**, so `orderBy: { createdAt: 'desc' }` is a coin flip
when two events land in the same tick — `reveal` + `skipped`, and `paused` +
`resumed`, do exactly that. The reconnect test then read `null` for the pause and
failed on CI but passed locally (timing luck). Fix: recovery reads the game log in
**one query** and matches by `questionId` in JS with **no ordering assumption** —
skipped = a `skipped` event exists; paused = `pauses > resumes` (they strictly
alternate, so a count is order-free); frozen remainder = `min(remainingMs of
pauses)` (successive pauses never increase it); anchor `openedAt` to "now" at
recovery so no historical pause timestamp is needed. Dropped the now-unused
`openedAt` field from the `paused` event. Lesson: never order `GameEvent` rows by
`createdAt` to decide "the latest event" — prefer an existence/count check keyed
by `questionId`.

## 2026-11-08 — programmatic E2E of the full gameplay flow

Verified the whole host+player+board loop end-to-end with real browser tabs
(`puppeteer-core`, chromium at `/usr/bin/chromium`), no screenshots — assertions
are DOM text only. Script lives in `/var/tmp/zpverify/e2e.js` (wiped on restart;
re-create from this note). Two players are required: with one player the engine
auto-reveals the instant they answer, which hides the host's `Reveal` button.

**19/19 checks pass, stable over 3 consecutive runs.** Covered: lobby PIN +
roster, question fan-out to host/both players, host reload mid-question
(resync), answer ack, reveal verdict + solution, leaderboard, advance, player
socket drop + auto-reconnect (`setOfflineMode`), answer after reconnect,
final placement/score, the "Keep your progress" account prompt, and the finished
game appearing in `/api/reports/games`.

**Engine auto-advance timings (real, by design):** `REVEAL_MS = 6000`,
`BOARD_MS = 6000`. So `reveal → board` after 6 s and `board → next question`
after another 6 s, with no host click. E2E must therefore not assume a
`Reveal`/`Next question` button is present — drive it with a tolerant helper that
clicks whichever of `Reveal`/`Leaderboard`/`Next question` is on screen, or waits
for the auto-advance. This cost several failed runs before being understood.

**Verified E2E-only failure modes (NOT product bugs):** the reveal screen shows
the word "Leaderboard" (the button) while already being the board; `body.innerText`
is upper-case for question meta (`QUESTION 1 OF 3`) — compare case-insensitively;
option text is `1 Paris` (number + label) with NBSP/whitespace — match after
stripping all whitespace.

**Dev-environment gotcha:** the backend integration suites call
`resetDatabase()` against the **same** `zeropeek_test` DB the dev backend uses, so
running `npm test` truncates the `User` table and deletes the bootstrap admin →
dev login then fails with 401 and `{"code":"unauthorized"}`. Restart the backend
(it re-runs bootstrap) before any browser E2E that follows a test run.

**backend 243/243, frontend 333/333, shared 102/102**, plus typecheck, build,

(3) `next`/`board` accepted illegal phases, so a stale timer could skip a whole
question — `next` only from `board`, `board` only from `reveal`.

backend process + real Chromium player UI, programmatic assertions only.

**Harness lessons (cost real time):**
- `npx tsx src/server.ts` re-execs, so SIGKILLing only the spawned child leaves
  the server alive and every "restart" test silently talks to the OLD process.
  Spawn with `detached: true` and `process.kill(-pid, 'SIGKILL')` the whole
  group, then assert `/api/health` is actually down before restarting.
- `Question.id` is a **global primary key**, so a fixture with hard-coded ids can
  only be seeded once per DB (`P2002` on the second run). Randomise the ids.
- On the host namespace the question event is `host:question`, not `game:question`.
- A host must go `reveal → board → next`; `host:next` straight from `reveal` is
  refused ("There is no leaderboard to advance from").
- A `slide` renders as "No answer" for the player (never graded) — that is
  correct, not a bug.
- `PublicPlayer` has no `rank` field; rank is the array position.
