## Phase 6.5.3 – extended host control (implemented, branch `feat/phase-6-5-3-extended-host-controls`)

Branched from `origin/main` `2fa0c6b` (PR #30 merged). Order from the owner: pause/resume +
skip for the host. Also folded in the two open questions from the 6.5.2 report (lobby kick
control, host presence for players).

**Pause/resume design (the part worth remembering):**
- `limitMs(question) = timeLimit*1000 + ANSWER_GRACE_MS` is now the ONE place the "visible
  limit + grace" arithmetic lives — the timer, the late-answer guard and the pause maths all
  call it. Before this, the same expression was written out three times and a resume would
  have drifted from the clock.
- Pause freezes `remainingMs` server-side, clears the timer, and **shifts `openedAt` forward
  by the pause duration on resume** — so elapsed-time scoring continues as if the pause never
  happened. Re-arms the timer exactly once.
- Paused state is persisted as rows in the **existing `GameEvent` log** (`paused`/`resumed`/
  `skipped`) → **no migration, no new column**. `recoverCurrentQuestion` reads the last of
  `paused`/`resumed` to restore a paused game **paused** (no timer armed), and the last of
  `question`/`reveal`/`skipped` to restore the skipped flag.
- `revealInternal` returns unchanged while paused **unless** it is a skip — so a stray timer or
  a racing host click cannot un-pause the game. `submitAnswer` refuses while paused.
- Slide questions have no clock → pause is refused by the engine, and the frontend offers no
  Pause button for them (dead-button guard).
- **Skip = end early, do NOT void.** Already-awarded points stand. That is the conservative
  choice and is flagged as an open product decision for chrisB in roadmap §6.2 + the report.
  **RESOLVED (chrisB, 2026-11-07):** a skip now **neutralises** the question — points refunded.

**Two dead-button bugs found and fixed by cross-checking the frontend against the engine:**
1. While paused the engine refuses a plain reveal, so offering **Reveal** was dead — a paused
   question now offers only Resume + Skip.
2. `engine.pause` refuses a `slide`, so the **Pause** button was dead for slides.

**Bug I found in my own work while reviewing the diff:** `playerSync` returned
`result: null` during a skipped reveal, but the *live* `game:reveal` sends
`outcome: 'skipped'`. So a player who reconnected mid-skip was shown the live question again
instead of the skipped result. Fixed in the engine (report `skipped` from `playerSync`), not
by patching the frontend — the sync must equal the live event. Regression test added:
"reports a skipped question to a reconnecting player, not a verdict".

**Also:** `answers` handler now keeps `currentAnswers` in step with the DOM, otherwise a
pause/resume re-render (which redraws from `currentAnswers`) showed a stale answer count.
Removed an unused `hasAnsweredCurrentQuestion` method I had added.

**Host presence:** `/host` room size decides `connected`/`reconnecting`, debounced
(`PRESENCE_DEBOUNCE_MS`) so a reload does not flash at players; first value for a game is sent
without waiting. Only reachability leaves the server — never a phase, session or host data.
Player chip renders **only** while the host is away.

**Kick:** now lobby-only (removing a player mid-game would silently rewrite a live ranking)
and it tells the player *first*, then removes the rooms, then re-broadcasts the lobby — so the
roster never lists someone already told to leave.

**Gate:** typecheck 0 errors; `prettier --check .` clean; tests **201 + 318 + 89 = 608** green;
`prisma migrate status` = up to date; `npm run build` OK. Integration cases run against real
Socket.IO + real Postgres (J/K/K2/K3/L in `host-sync.integration.test.ts`, a "pause / resume /
skip" + slides block in `engine.integration.test.ts`, skip-report case in
`snapshot.integration.test.ts`).

**Owner decisions (chrisB, 2026-11-07) — the three open questions are now CLOSED:**
- **A. Skip neutralises the question.** Already-awarded points are refunded, the correct answer
  is neutralised, earlier questions untouched. New engine method `refundQuestion` does it in one
  transaction (idempotent → a re-entrant skip or a skip racing an end cannot double-refund).
  Every report marks the question as skipped: `gameReport.skipped`, a CSV `skipped` column,
  `quizStatistics.skippedGames`.
- **B. No solution on a skipped reveal.** `HostReveal` is a discriminated union whose skipped
  variant carries only `{ id, type, text }` — a leak is impossible **by construction**. The
  frontend `revealBody(reveal)` is the one pure builder for the reveal screen.
- **C. A slide cannot be paused.** Engine refuses pause/resume for a `slide`; the host console
  offers no Pause button. Tests added on both sides.

Docs: `docs/reports/phase-6-5-3-extended-host-controls.md`, roadmap §6.2, `docs/phases.md`.

**Owner approved (2026-11-07): complete the phase and open a DRAFT PR** (explicit exception to
the standing "no PR without approval" rule). No merge, no deploy — that stays with chrisB.

**CI caught a real bug (worth remembering):** `GameEvent.createdAt` is
**millisecond precision only**, so `orderBy: { createdAt: 'desc' }` is a coin flip
when two events land in the same tick — `reveal` + `skipped`, and `paused` +
`resumed`, do exactly that. The reconnect test then read `null` for the pause and
failed on CI but passed locally (timing luck). Fix: recovery reads the game log in
**one query** and matches by `questionId` in JS with **no ordering assumption** —
skipped = a `skipped` event exists; paused = `pauses > resumes` (they strictly
alternate, so a count is order-free); frozen remainder = `min(remainingMs of
pauses)` (successive pauses never increase it); anchor `openedAt` to "now" at
recovery so no historical pause timestamp is needed. Dropped the now-unused
`openedAt` field from the `paused` event. Lesson: never order `GameEvent` rows by
`createdAt` to decide "the latest event" — prefer an existence/count check keyed
by `questionId`.

**Engine auto-advance timings (real, by design):** `REVEAL_MS = 6000`,

the word "Leaderboard" (the button) while already being the board; `body.innerText`
is upper-case for question meta (`QUESTION 1 OF 3`) — compare case-insensitively;
option text is `1 Paris` (number + label) with NBSP/whitespace — match after
stripping all whitespace.

## Phase 6.8.4 — progression curve, reward matrix, inventory management, presentation
(branch `feat/phase-6-8-4-progression-inventory-podium`, base `main` @ `7676880`; report
`docs/reports/phase-6-8-4-progression-inventory-podium.md`)

- **Level curve replaced (binding, owner-fixed):** `requiredXp(level) = 100000 + (level-1)*10000`;
  `xpForLevel` = 0 / 100000 / 210000 / 330000 / … (L1→2 costs 100k). The old Phase-5c table
  (10k/level, +1k from L11) is **dead** — do not reintroduce. `xpCostForLevel` renamed `requiredXp`.
- **XP is never lost on a curve change:** `PlayerProfile.xp` is the truth; `level` is derived from
  it on **every** read and the stored `level` column is repaired to match (idempotent, no XP write).
  A more expensive curve can *lower* an existing account's displayed level — documented, intended.
- **Reward matrix is SLOT-based, not item-based** (`shared/levelRewards.ts`): `LEVEL_REWARDS`
  = L2 outfit, L3 backpack, L4 neckAccessory, L5 visor, L6 wristAccessory. The concrete item is the
  **chosen character's own** item for that slot (`levelRewardItem(level, characterId)`), so the
  matrix is character-independent and extensible. **L7+ intentionally has no entry** — grants
  nothing, never blocks XP/level. Do not invent L7 items.
- **Level 1 = nothing equipped.** `defaultAvatarConfig` now returns `EMPTY_EQUIPMENT`; the old
  per-character "default kit" (all items `unlockStatus:'available'`) is gone. `unlockStatus` was
  **removed** from `CosmeticItem`. Ownership = a `PlayerInventory` row exists.
- **`reconcileLevelRewards(userId, level, characterId)`** is the single mechanism keeping three cases
  correct with one path: existing account under the old curve, character switch, and repeat calls.
  Inserts `rewardItemsUpToLevel(level, characterId)` with `skipDuplicates` (`@@unique([userId,itemId])`).
  Runs in the grant tx, on `PUT /api/profile` (character change), and on **every read** of
  progress/inventory/equip — so an account self-heals. It never touches XP.
- **New endpoint** `POST /api/inventory/unequip` (body: only `slot`; extra fields rejected). Equip
  reconciles first so a just-reached reward is equippable immediately.
- **Profile/inventory split (final):** profile = character choice + stats + level/XP + achievements;
  inventory = items + loadout with per-slot **Unequip** and per-item Equip/Unequip. Profile links to
  inventory ("Open inventory"). The avatar *editor* was removed from the profile.
- **Presentation:** `playerAvatar(nickname, avatar, {size, crop:'head'|'full'})`. `head` = CSS
  `object-fit:cover; object-position:center top` on a square frame (in-game surfaces, leaderboard);
  `full` = `contain`/`bottom` (winner podium, whole figure). **No image is edited/generated** — only
  the existing WebP is framed in CSS. New `playerBadge(nickname, avatar, {level,xp}|null)` shows the
  head + `Level n · x XP`; player page reads `/api/progress` once at boot (best-effort → omit line).

  there AND defined in `tokens.css`. Removed the now-dead `question__who-name` from both.

## Phase 6.8.5 — Clock synchronisation & socket rate limiting (branch only, no push)

Branch `feat/phase-6-8-5-socket-security-clock-sync` from `main` @ `c3ffb70`. Owner approved
6.8.5 after the recon pass. Report: `docs/reports/phase-6-8-5-clock-sync-and-socket-rate-limit.md`;
roadmap §9.3; ADR 0006 updated.

**Clock sync**
- `shared/src/clock.ts` (NEW, pure): NTP model `offset = serverTime − (t1+t3)/2`,
  `CLOCK_SAMPLE_COUNT = 5`, `CLOCK_MAX_ROUND_TRIP_MS = 2000`, `offsetOfSample` / `bestOffset`
  (best = smallest round-trip; ties → later sample; unusable samples dropped, **not** clamped).
- `shared/src/events.ts`: `ClockPing`/`ClockPong` + `clock:ping` (c→s) / `clock:pong` (s→c) on
  **both** the player `/` and host `/host` maps. `answerClockPing` in `socket.ts` echoes the id,
  emits the event **and** answers an ACK if given; id validated, never trusted. **Not** rate-limited
  (cheap, stateless, a burst is how it's meant to work).
- `frontend/src/clockSync.ts` (NEW): sequential probes, pong correlated by id (stray/duplicate
  ignored), measures round-trip with `performance.now()` (monotonic), `serverNow()` falls back to
  `Date.now()` before the first sample (exact pre-6.8.5 behaviour). One instance per socket;
  `sync()` re-run on every reconnect; overlapping callers share one round.
- `pages/host.ts`: `startTimer` + `resumed` handler now read `clock.serverNow()` instead of
  `Date.now()`. **Display-only** — the server's deadline is unchanged (integration test proves a
  corrected clock can't get a 2nd answer accepted).

**Socket rate limiting**
- `backend/src/socketRateLimit.ts` (NEW): `SocketRateLimiter` token bucket, `(rule,key)` windows,
  injectable `now`, `enabled` flag, `consume`/`check`/`reset`. Rejected call doesn't spend a token
  or extend the window.
- `SOCKET_RATE_RULES`: join 10/10s, joinByAddress 60/10s, answer 20/10s, rejoin 15/10s,
  rejoinBySocket 20/10s. Address/socket keys are **looser backstops** (so cycling reconnects can't
  reset the primary bucket), never an identity.
- Key is always **server-owned**: `socket:<id>` before a seat, `player:<playerId>` after. A client
  field (extra `playerId`, different `questionId`) can never move a bucket.
- `config.socketRateLimits` ← `SOCKET_RATE_LIMITS` (default on outside `test`, off in `test` unless
  set) — **same pattern as `authRateLimits`**; without this the many existing socket suites trip.
- Wired into both compose files (`:-true`), `.env.portainer.example`, PORTAINER.md, ENVIRONMENT.md.

**Tests (all green, DB reachable, 0 skips):** shared 165→179, frontend 458→469, backend 350→385

## Phase 6.9.1 — server states & event contracts (branch `feat/phase-6-9-1-server-show-state`)

Branched from `origin/main` `177b63c` (PR #46 merged). Order: the **foundation** of the Game-Show mode
only — the real `lead` phase, `category`/`difficulty` on `PublicQuestion`, and the per-player
points/rank deltas. No scene, no CSS, no background image, no schema change.

### What was built
- **`lead` is a real server phase now.** `engine.startInternal` → `enterLead`; fixed window
  `LEAD_SECONDS = 5` (`LEAD_MS`). New engine event `lead`, fan-out `host:lead` (host ns) +
  `game:lead` (player ns). `advanceFromLead` and `skipLead` both run under `withPhaseLock` and both
  bail unless `phase === 'lead'`, so exactly one question opens even if the timer races a skip.
- **Recovery re-arms the REMAINING window.** Added `'lead'` to the recovery event-type filter in
  `load()`; rebuilds `endsAt` from the persisted `lead` event and sets `game.timer` to
  `endsAt − Date.now()`. If already expired, advance via `setTimeout(…, 0)` (deferred: the runtime
  is not yet in `games` until `load` returns).
- **Clock:** reuse Phase 6.8.5 `ClockSync` only. `pages/player.ts` now constructs a `ClockSync`,
  `sync()`s on boot and again on every `connect`; both host and player compute the displayed number
  from server `endsAt` vs `clock.serverNow()`.
- **`host:skipLead`** host command (session-guarded); legal only in `lead`. Duplicate → engine
  `conflict('There is no countdown to skip.')`. No new client-reachable player event (so no
  rate-limit change; `game:lead` is server→client only).
- **Additive contracts:** `PublicQuestion.category?/difficulty?` (forwarded by `publicQuestion`, only
  when present; never a solution field); `LeadState`, `PointsDelta`, `RankDelta`; `PlayerSync.lead`,
  `HostState.{lead,points,ranks}`; `host:reveal` gains `points`, `host:board` gains `ranks`.
  `hostState()` became `async`.
- **Deltas read from the DB, not recomputed:** `pointsDeltas()` sums `playerAnswer.points` per player
  and sets `previousScore = score − delta`; `rankDeltas()` re-ranks with each player's own delta
  removed. Read-only ⇒ idempotent, and identical live vs. after `evict`+reload (asserted).
