# 2026-11-06

## Phase 6.2 analysis (Navigation, player surface, host dashboard) – plan only, no code
- Base: `origin/main` = `f2f06c5` (PR #20 merged). Worktree clean, on `main`.
- Frontend is a **multi-page vanilla-TS** app: `index.html` (player), `host.html` (host **and**
  beamer combined), `editor.html`, `admin.html`. One `<main id="app">` per page, one entry TS each.
  Caddy serves with `try_files {path} {path}.html`, so `/host` and `/host.html` both work.
- **There is no navigation at all today.** Every page is one screen; the only "nav" is buttons that
  do `location.href = './host.html'` etc. No sidebar, no bottom bar, no `shell`/`nav__` CSS
  (`grep -c shell|sidebar|nav__|app-nav` → 0).
- Layout primitives: `.wrap` (max-width `--content-max` 1180px → 1320px ≥1440) and `.centered`
  (`min-height:100dvh; display:grid; place-items:center`). `.centered` also carries the **starfield**
  (backdrop.css `.centered::before`) — so every `.centered` screen shows the starfield, not just login.
- Existing components in `ui.ts`: brand, pageHeader, field, button, setBusy, chip, progress,
  statTile, dialog, confirmDialog, skeleton, countdown, emptyState, notice, errorText, toast,
  spinner, screen, escapeCsv. `grid--2/--3` are auto-fit minmax, not fixed.
- Player: **no profile, no level, no XP** anywhere (XP is Phase 6.6/6.8). So "Kopfbereich mit Profil,
  Level, XP" has no data source yet — must be a placeholder or deferred; flag to owner.
- Roles today: `ADMIN`, `TRAINER` only. No `PLAYER` (Phase 6.3). "HOST"/"SPIELER"/"BEAMER" in the
  6.2 brief are **capabilities**: host = authenticated (TRAINER/ADMIN) on `/host`; player = anonymous
  socket join on `/`; beamer = the `.show` surface inside `host.html`. Server authority unchanged.
- Socket events (server `socket.ts`): host:* create/join/start/next/reveal/board/end/kick,
  player:join/rejoin/answer. No pause/resume/skip events exist.

### 6.2.1 result (implemented on `feat/phase-6-2-1-navigation-shell`)
- New `src/navigation.ts`: `appShell(opts)` builds one node rendered into `<main>`; **additive**,
  no new HTML entry, all four URLs untouched. Exports `ShellRole`, `NavItem`, `PLAYER_NAV`,
  `HOST_NAV`, `ADMIN_ITEM`, `navItems(role,{isAdmin})`, `mobileNavItems(...)`,
  `MOBILE_PRIMARY_LIMIT=5`, `isAvailable`, `appShell`.
- `AppShellOptions`: `role, active, title?, badge?, brandHref?, isAdmin?, actions?, children`.
  The shell owns the single `<h1>` (so `pageHeader` is no longer used by any page — still exported).
  Admin entry appended only for `role:'host' && isAdmin`. Player nav has **no** sign-out.
- Unbuilt entries render as `span.nav__item--soon` (`aria-disabled`), never a dead link.
  Bottom bar = first 5 + `<details class="nav__more">`; the overflow entry that is current gets
  `.nav__more-item--active` + the summary gets `.nav__item--active` (admin-on-phone case).
- **Page integration:** `player.ts` local `shell(active,content)` wrapper (all 6 renders + reconnect);
  `host.ts` overview + report wrapped, **beamer `.show` screens left unwrapped**; `editor.ts` list +
  edit wrapped, boot now reads `session.user.role` into `isAdmin`; `admin.ts` wrapped with
  `brandHref: './admin.html'`.
- **Tokens:** `--sidebar-w 248px`, `--sidebar-w-compact 72px`, `--bottom-bar-h 60px`,
  `--shell-top-h 64px`, `--player-measure` (100% phone / 90% ≥768 / 78% ≥1024 / 1000px ≥1440),
  `--player-gutter: var(--space-4)`. Measure applied to `.shell--player .centered > *`, not the card.
- **Tests:** `navigation.test.ts` (20) + design-system class/token guards (now 143). Frontend 210,
  backend 98, shared 66 = **374 green** with the DB up. Typecheck, `prettier --check .`, build all pass.
- **Geometry probe** (headless Chromium, real tokens.css, mirrored shell DOM): `cardCentered=0` at
  390/768/1024/1280/1920; player card 468→598→580→780→**1000** (cap works); no horizontal overflow.
- **Gotcha:** the "player-measure basis" is the *centred section* (full shell-body width), so at
  1920 a 78% step would be 1304px — the 1000px cap is what actually limits it. Doc says so now.
- Nav "soon" items (Questions/Inventory/Profile/Settings, Game control/Backgrounds/Players/…)
  are the agreed placeholder approach; owner approved folding brand+actions into the shell top bar.
